# 검증 기록 (2026-09-19)

## 빌드

`gradlew.bat assembleDebug`가 ARM64와 x86_64 구성에서 성공했습니다. 앱 버전은 0.2.0이며 두 ABI를 포함하는 디버그 APK는 약 12.8MiB입니다.

## 자동 게임 로직 테스트

`native/tests/CastleModelTests.cpp`를 Android 실행 파일로 빌드해 실행했습니다. 기본 로직은 연결된 ARM64 기기에서, 최종 합성 특성까지 포함한 테스트는 API 36 x86_64 전용 에뮬레이터에서 통과했습니다.

- 재화 부족·잘못된 인덱스·전투 중 변경을 거부합니다.
- 방 확장 순서, 자리 교환, 인접 서고의 함정 보너스를 확인했습니다.
- 모든 합성 조합, 레벨 계승, 재료 소모, 도감 보존을 확인했습니다.
- 드래곤 광역 피해와 왕관 슬라임 회복을 확인했습니다. 쓰러진 마물은 전투 중 회복으로 부활하지 않습니다.
- 저장 파일 교체·재읽기·손상된 입력 거부·결과 화면 재실행 시 보상 중복 방지를 확인했습니다.
- 30Hz와 60Hz 업데이트의 전투 결과가 일치했습니다.
- 패배 시 마물과 보급품이 남고 같은 날에 재도전할 수 있었습니다.
- 시작 재화로 첫 합성을 한 뒤 낮은 레벨의 마물을 먹이고 골렘을 추가하는 전략으로 10일 캠페인을 10회 방어 만에 완료했습니다. 이는 완주 가능성 검증이며 재미나 전체 전략의 밸런스 검증은 아닙니다.

최종 에뮬레이터 실행에서 100회 방어 시뮬레이션에 약 4.7ms가 걸렸습니다. 이 수치는 그래픽·오디오를 제외한 로직 비용이며 전체 앱의 FPS 측정값이 아닙니다.

## 화면과 조작

API 36 전용 에뮬레이터에서 1080×2400 및 720×1280 화면으로 확인했습니다. 먹이 → 합성 상대 선택 → 결과 미리보기 → 합성 → 도감 → 앱 강제 종료·재실행 → 방어 → 보상 → 다음 날의 흐름을 검증했습니다. 짧은 화면에서 하단 도움말과 알림 사이 간격을 추가했습니다.

한국어 글꼴은 아틀라스에 1024×646 크기로 올라갔으며 게임 로그에서 글꼴·GL·앱 크래시 오류를 발견하지 않았습니다. 연결된 실제 휴대폰에서는 초기 실행 화면을 확인했고, 이후 다른 앱 작업이 진행 중인 것을 확인하여 UI 검증을 전용 에뮬레이터로 옮겼습니다.

## 남은 검증

장시간 배터리·GPU 프레임 프로파일링, 다양한 실기기에서의 장기 플레이테스트, 수집 동기와 난이도에 대한 사용자 평가는 남아 있습니다. 현재 결과를 상용 게임 수준의 콘텐츠·밸런스 검증으로 해석하지 않습니다.

## 코드 리뷰 후 추가 검증

같은 Android 입력 버퍼에서 합성 확인이 연속 실행되면 소모된 마물 인덱스에 접근할 수 있었습니다. 행동 직후 hit 목록을 폐기하고 BACK에서 진행 중인 제스처도 취소하도록 수정했습니다. CastleSceneTests는 실제 Scene의 렌더링 배치로 입력 영역을 만든 뒤, 합성 직후 연속 탭·BACK 직후 손가락 떼기·다음 프레임 입력 복구를 검증합니다. 그래픽 출력은 생략하는 테스트입니다.

2026-09-19 ARM64 실기기에서 CastleModelTests와 CastleSceneTests가 통과했고, 수정된 ARM64·x86_64 Debug 빌드와 lintDebug가 통과했습니다. 자동 생성 설명 중 존재하지 않는 Monster.cpp 참조, 도감 등록 과정, EGL 소유자와 실제 전투·저장 조건을 코드와 대조해 수정했습니다. 스레드·성능의 기기별 미검증 범위는 threading.md에 유지합니다.
