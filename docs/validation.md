# 무천 SRPG 검증 기록 — 2026-09-20

## 0.6.0 그래픽 시제품

ARM64·x86_64 Debug/Release 빌드와 lint가 통과했습니다. JVM testDebugUnitTest는 NO-SOURCE입니다. Galaxy S25+ SM-S936N / Android 16 ARM64와 API 36 x86_64 에뮬레이터에서 모델·표현·Scene 네이티브 검사가 통과했습니다. 버전은 0.6.0, versionCode 7입니다.

새 검사는 안전 영역·여백의 터치 좌표, 네 방향, 이동과 밀림 보간, Chase·Collision 예고의 피해 중복 방지, 방어를 반영한 Hit 수치와 원본 상태 불변성을 확인합니다. 모델의 이동 이벤트는 점유 칸을 피한 BFS 경로를 한 칸씩 출력합니다. 명령의 시각 재생 최종 체력·좌표도 확정 모델과 대조합니다. 기존 다섯 맵 완주 결과는 아래 0.5.0 기록과 같습니다.

2400×1080과 1280×720 에뮬레이터에서 이야기 선택 → 도장과 큰 초상화, 한국어, 가로 전장, 연출 절제 설정의 재실행 유지 상태를 확인했습니다. 최종 APK 업데이트 전후 WUTEN 2 저장 문자열이 완전히 같은 것을 확인했습니다. native/tests/VisualFixtures.cpp로 만든 배치를 에뮬레이터에만 주입해 발경과 기공파를 실제 터치로 사용했습니다.

| 재현 장면 | 확인한 결과 |
|---|---|
| 발경·추격, 관계 2 | 예상 피해 21·추격 1. 적 (3,2)→(4,2), 체력 30→9, 로시 기 100→90, 학선인 추격 사용으로 저장됐습니다. 영상의 첫 타격 숫자는 -10입니다. |
| 기공파 | 같은 직선의 두 적이 각각 체력 30→10, 란란 기 100→60으로 저장됐습니다. 영상에서 직선 빔과 피해 숫자를 확인했습니다. |
| 실기기 업데이트 | 같은 서명의 Release APK로 기존 설치를 삭제하지 않고 0.6.0으로 업데이트했고 패키지 버전을 확인했습니다. 실기기는 보안 잠금 상태이므로 새 게임 화면과 저장 진행의 직접 대조는 아직 하지 못했습니다. |

캡처·영상은 로컬 build/visual-story.png, visual-base.png, visual-combo-preview.png, visual-impact.png, visual-combo.mp4, visual-beam.png, visual-beam.mp4입니다. 재현용 배치는 자연 플레이나 재미 검증으로 취급하지 않습니다. 한국어 추가 글리프는 303개입니다.

코드 리뷰에서 이동 직선 보간, 사망 직후 결과 화면 전환, 타격과 추격의 체력 중복, 연출 중 다음 명령의 피해 표시를 점검했습니다. 이동 경로 이벤트, 종료 지연, Hit만 적용하는 재생과 연출 중 안내 표시로 해결했습니다. 전투 수치·성장·저장 형식은 유지합니다.

픽셀 테마는 한 개이며 다섯 맵의 장애물만 다릅니다. 초상화 원본은 인물당 418px로, 제안한 512px보다 작습니다. 실제 기기 새 그래픽의 장시간 성능·배터리·오디오 라우트 변경은 미검증입니다. 0.5.0 프레임 측정을 새 아트 성능 수치로 재사용하지 않습니다.

## 0.5.0 기록 (이전 캠페인 구현)

### 빌드와 자동 검사

0.5.0 (versionCode 6)에서 ARM64·x86_64 Debug/Release 빌드와 lint가 통과했습니다. `assembleDebug assembleRelease testDebugUnitTest lintDebug --no-daemon`을 실행했으며 JVM 테스트는 NO-SOURCE입니다.

Galaxy S25+ (SM-S936N), Android 16, ARM64와 API 36 x86_64 에뮬레이터에서 `tools/test-srpg.ps1`의 모델·Scene 검사가 통과했습니다.

- 단계별 명령 거부, 이야기 선택 한 번 적용, 수련 제한·장비·연구 자원, 출전 최소 인원·배치 교환을 검사했습니다.
- 아군마다 한 번 행동, 마지막 아군 뒤 적 차례, 잘못된 명령의 상태 보존, 예측과 실제 이벤트·피해·기 일치를 검사했습니다.
- 밀기와 동료 추격, 적끼리 충돌, 기공파 관통, 이동 후 자신 회복, 열 기술 실행·비용, 점혈, 노출된 기 모음을 검사했습니다.
- 재도전의 배움·발견·약초 복원, 패배 후 거점 복귀, 마지막 라운드 승리 우선, 시간 초과, 보상 중복 방지를 검사했습니다.
- 저장 재읽기·후행/불완전 데이터 거부·불가능한 보상 이력·비전투 단계의 오염된 좌표 거부를 검사했습니다. 검토 중 비전투 Unit 검증 누락을 발견해 수정했습니다.
- 실제 Scene 입력 대상으로 스토리·도장·배치·전투 전환, 배치 교환, 중복 확정, 연출 입력 잠금, BACK 이동 취소, 안내/턴 종료 모달과 저장 일치를 검사했습니다.

공개 모델 명령을 사용하는 단순 정책으로 다섯 맵을 연속 완주했습니다. 각 승리에서 저장·불러오기를 수행하고 보상을 두 번 요청해도 한 번만 적용되는지 확인했습니다.

| 1 | 3 | 84 | 0 |
| 2 | 5 | 68 | 1 |
| 3 | 9 | 88 | 0 |

이는 완주 회귀 경로이며 재미·균형·모든 편성의 완주를 보장하지 않습니다.

### 화면과 저장 복원

실기기의 기존 0.4.0을 삭제하지 않고 서명 Release 0.5.0으로 업데이트했습니다. 1440×3120에서 이야기·도장·진행 중 전투의 한글과 조작 영역을 확인했습니다. 새 캠페인은 독립된 wuten-v2.txt를 사용하며 이전 수련장 진행을 자동 변환하지 않습니다.

1080×2400과 720×1280 에뮬레이터의 전투 화면을 확인했습니다. 1080×2400에서는 테스트 모델로 만든 재현용 배치를 불러오고 실제 화면에서 기술 → 발경 → 확정을 조작했습니다. 예상 피해 18·기 -10·추격 1이 실제 적 체력 30→12, 로시 기 100→90, 학선인의 추격 상태와 일치했습니다. 강제 종료·재실행 전후 저장 문자열이 유지되는 것을 확인했습니다. 이 장면은 연계 검증용 배치이며 자연 플레이 완주 기록으로 취급하지 않습니다.

한국어 추가 글리프는 290개입니다. 임시 도형 캐릭터를 사용합니다. 캡처는 로컬 build의 campaign-story.png, campaign-base.png, campaign-phone-battle.png, campaign-combo-before.png, campaign-combo-preview.png, campaign-combo-after.png, campaign-short.png입니다.

### 성능 측정과 한계

실기기 네이티브 SurfaceView의 짧은 SurfaceFlinger 표본 126개에서 표시 간격 중앙값 8.342ms, 95백분위 8.343ms, 최대 8.343ms를 관찰했습니다. 약 120Hz 표시 시점의 표본이며 CPU/GPU 개별 비용·장시간 전투·배터리·모든 기기 성능을 보장하지 않습니다. 원시 표본은 로컬 build/campaign-phone-frametimes.txt입니다.

10,000회 모델 미리보기는 ARM64에서 약 1.98ms, x86_64 에뮬레이터에서 약 0.85ms였고 체크섬은 10,000입니다. 이 측정은 적 차례가 발생하지 않는 간단한 명령이며 전체 게임 FPS가 아닙니다.

추격을 많이 하지 않아도 완주하는 정책이 발견됐으므로 맵 배치와 연계 동기의 플레이테스트가 필요합니다. 상세 내용은 [밸런스 보고서](../design/balance/balance-check-campaign-2026-09-20.md)에 기록합니다. 최종 아트·상세 서사·절벽·지형 파괴·개별 인물 관계·전체 성장기와 장시간 오디오 라우트 검증은 후속 범위입니다.
