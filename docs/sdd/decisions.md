# SRPG 설계 결정

## D-001 C++ 핵심 엔진과 Android 플랫폼 계층을 유지한다

사용자의 확정 요구입니다. GameActivity·OpenGL ES·AAudio·한국어 글꼴·햅틱을 재사용하고 게임 규칙은 별도 C++ 모델에 둡니다. 범용 엔진을 교체하는 일보다 전투 중 배움의 재미를 먼저 검증합니다.

## D-002 세 수련전으로 간파·모방·체득을 검증한다

첫 서사 장 전체를 구현하기 전에 철산격 한 기술과 세 도장 맵에 집중합니다. 관찰 횟수를 쌓는 대신 동작·회피·방어라는 서로 다른 경험을 요구합니다. 성공한 모방은 전투 도중 자기 기술로 바뀌고, 다음 수련으로 이어집니다.

## D-003 첫 시제품은 결정적 전투를 사용한다

명중 난수 대신 미완성 기술의 높은 기력 비용과 노출 피해로 위험을 표현합니다. 예측과 실제 결과가 일치해 플레이어가 자신의 선택을 이해할 수 있어야 합니다. 향후 난수를 넣을 경우 예측·저장·재현 규칙을 함께 바꿉니다.

## D-004 확정 명령을 원자적으로 처리한다

작은 1 대 1 수련전에서는 아군 행동과 상대 응답을 한 명령으로 해결합니다. 별도의 실시간 AI 갱신을 두지 않습니다. 동료 진영 턴과 여러 상대를 추가할 때에는 명령 단위와 연출 이벤트를 확장해야 합니다.

## D-005 기 축적과 공간 제어를 연결한다

안전한 위치에서 기를 모으고, 더 모으려다 맞으면 손해를 봅니다. 체득한 붕권은 상대를 밀거나 벽에 충돌시켜 다음 공격을 끊습니다. 기를 단순한 전투 전 보유 MP로 취급하지 않습니다.

## D-006 배포 식별자는 유지하고 게임 구현은 교체한다

프로젝트·라이브러리·namespace·테마는 무천 이름을 사용합니다. 이미 설치된 앱의 업데이트 경로를 유지하기 위해 applicationId만 그대로 둡니다. 새로운 수련 저장은 독립된 파일과 버전을 사용하며 기존 게임 데이터를 임의 변환하지 않습니다.

## D-007 현재 구현과 목표 설계를 구분한다

전체 이야기는 어린 무천도사부터 손오공과의 만남까지입니다. 세 수련전에는 본편 시나리오·동료 파티·장기 성장 트리·고저차·지형 파괴를 구현하지 않았습니다. 이 차이를 [게임 방향](../game-direction.md)과 [SRPG 설계](../srpg-design.md)에 명시합니다.
